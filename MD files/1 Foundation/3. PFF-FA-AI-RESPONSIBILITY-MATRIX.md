# PFF-FA Enterprise Agentic AI Platform — Responsibility Matrix

**Document ID:** PFF-FA-AI-RESPONSIBILITY-MATRIX  
**Version:** 1.0.0  
**Status:** Development Baseline  
**Platform:** PFF-FA Enterprise Agentic AI Platform / Adam AI  
**Purpose:** Define ownership boundaries between the existing PFF-FA Enterprise Platform and the AI Platform.

---

# 1. Purpose

This document establishes the authoritative responsibility boundary between:

1. Existing PFF-FA Enterprise Applications and Services
2. PFF-FA AI Platform
3. External AI/Infrastructure Dependencies

The primary objective is to prevent duplicated business logic, unclear ownership, unauthorized AI behavior and architectural overlap.

The AI Platform must extend the enterprise ecosystem without replacing authoritative enterprise capabilities.

---

# 2. Core Responsibility Principle

> **Enterprise systems own business truth and business execution. The AI Platform owns conversational intelligence, AI orchestration, contextualization, controlled tool usage and AI quality.**

A responsibility must have one clear authoritative owner.

Where two platforms participate in the same capability, the distinction must be explicit:

```text
Enterprise = Authority / Execution
AI Platform = Interpretation / Orchestration / Context / Communication
```

---

# 3. Responsibility Classification

Each capability is classified as:

| Classification | Meaning |
|---|---|
| **E-OWN** | Enterprise owns the capability and authoritative decision |
| **AI-OWN** | AI Platform owns the capability |
| **E-AI** | Enterprise and AI Platform both participate with clearly separated responsibilities |
| **EXT** | External platform/provider owns the capability |
| **CONSUME** | AI Platform consumes the capability but does not own it |
| **NOT-APPLICABLE** | Capability is outside the platform boundary |

# 5. Identity and Access Responsibility

## 5.1 Authentication

### Enterprise responsibility

Enterprise identity infrastructure is authoritative for:

- User authentication
- Token issuance
- Token validation
- MFA
- Identity lifecycle
- Identity federation

### AI responsibility

AI Platform:

- Receives authenticated request
- Extracts approved identity context
- Associates identity with conversation/session
- Propagates correlation and user context
- Uses identity information for AI runtime decisions

AI Platform must not independently authenticate the user when the enterprise authentication boundary already exists.

---

## 5.2 Authorization

The agreed architecture is:

```text
User
 ↓
Enterprise Identity
 ↓
APIM
 ↓
Authorization Policy
 ↓
Validated Claims
 ↓
FastAPI
 ↓
AI Runtime
```

### Enterprise owns

- Authorization policy
- Role assignment
- Claims generation
- APIM authorization
- Enterprise resource authorization

### AI owns

- Consuming claims
- Applying workflow/tool allow-lists
- Filtering AI context
- Preventing unauthorized tool selection
- Enforcing defense-in-depth controls

The AI Platform does not override an APIM authorization decision.

# 47. Conflict Resolution Rules

If two sources disagree:

## Rule 1 — Enterprise operational state wins

```text
ERC vs Enterprise API
→ Enterprise API wins
```

## Rule 2 — Enterprise authorization wins

```text
AI assumption vs APIM claims
→ APIM/enterprise authorization wins
```

## Rule 3 — Enterprise business rule wins

```text
SLM reasoning vs Enterprise rule result
→ Enterprise result wins
```

## Rule 4 — Current authoritative source wins over cache

```text
Cache vs current enterprise response
→ Current enterprise response wins
```

## Rule 5 — Human enterprise decision wins

```text
AI suggestion vs HIL decision
→ HIL decision wins
```

```text
Enterprise API / Enterprise Event
            >
           ERC
            >
           Cache
            >

            >
```

The AI Platform owns AI reasoning execution.

# 69. Responsibility for AI Evaluation Gates

A release may be blocked when:

- Tool selection regresses
- ERC grounding regresses
- Hallucination increases
- Security tests fail
- Prompt injection tests fail
- Response quality falls
- Latency exceeds defined threshold
- Cost exceeds approved threshold

AI Platform owns these AI quality gates.

Enterprise may provide business acceptance criteria.

# 73. Change Control

Any proposed change that moves responsibility from Enterprise to AI Platform, or vice versa, must be reviewed through the agreed architecture governance process.

Examples:

- AI implementing a business rule
- AI directly accessing an enterprise database
- AI replacing an enterprise workflow
- AI owning a business transaction
- AI bypassing APIM authorization
- AI making a human/enterprise approval decision
- RAG becoming an operational source of truth

Such changes require explicit architecture approval.
