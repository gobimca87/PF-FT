

# 158. Final Performance & Cost Principles

1. **Measure the complete user-to-AI-to-enterprise path.**
2. **Optimize the critical path rather than individual components in isolation.**
3. **Use p95/p99 for production latency decisions where appropriate.**
4. **Separate time-to-first-token from total completion time.**
5. **Use asynchronous execution for I/O-bound workloads.**
6. **Use parallelism only for genuinely independent operations.**
7. **Bound all concurrency.**
8. **Never use unbounded agent loops.**
9. **Bound retries and prevent retry amplification.**
10. **Use the agreed ERC batching strategy, initially 20 teams per loop.**
11. **Explicitly capacity-test 100+ teams and 100+ officials.**
12. **Track token usage at request, agent, workflow and model levels.**
13. **Treat context size as both a latency and cost driver.**
14. **Optimize context without losing authoritative information.**
15. **Measure RAG and SLM latency independently.**
16. **Measure CPU, memory, GPU and VRAM where applicable.**
17. **Autoscaling must consider AI-specific constraints, not only CPU.**
18. **Model routing can optimize quality, latency and cost together.**
19. **Fallback models must be approved and evaluated.**
20. **Caching must respect authorization and freshness.**
21. **Do not optimize by weakening security, authorization or guardrails.**
22. **Do not optimize by removing required enterprise-authoritative data.**
23. **Cost must be measured per workflow, not only per API request.**
24. **Cost allocation should support environment, component, workflow and model dimensions.**
25. **Budgets and cost guardrails must be configurable.**
26. **Cost anomalies must be observable.**
27. **Performance and cost regressions must be part of release validation.**
28. **Every performance optimization must be evaluated for AI-quality impact.**
29. **Every major model, prompt, RAG or infrastructure change requires a new baseline.**
30. **Performance engineering is continuous; production telemetry must feed future capacity and optimization decisions.**
31. **The final optimization target is not minimum cost or minimum latency alone, but the best enterprise balance of quality, reliability, security, latency and cost.**
