
```text

Testable

Observable
Versioned
Reviewable
Scalable
Consistent
Enterprise-ready
```

Prefer:

```text

 ↓

 ↓

 ↓

 ↓
```

```text

Prompt → direct secret access

```

Dependencies should point inward toward stable abstractions.

Example:

```text

 ↓

 ↓
Interfaces
 ↓
Infrastructure implementations
```

```text
FastAPI
Langfuse
Azure SDK
Provider SDK
Database implementation
```

where avoidable.

The project must pin and explicitly manage the supported Python version.

Development and CI environments must use the same supported version range.

# 14. Type Annotation Standard

Public functions, interfaces and important internal methods should use explicit type annotations.

Example:

```python
async def execute_workflow(
    request: WorkflowRequest,
) -> WorkflowResponse:
    ...
```

Avoid unnecessary use of:

```python
Any
```

unless justified.

# 18. Naming Standard

Use clear names.

Python:

```text
snake_case
```

Classes:

```text
PascalCase
```

Constants:

```text
UPPER_SNAKE_CASE
```

Example:

```python
class ERCContextBuilder:
    ...

MAX_ERC_BATCH_SIZE = 20
```

---

# 19. File Naming

Python modules should use:

```text
snake_case.py
```

Avoid ambiguous names such as:

```text
utils.py
helpers.py
misc.py
common2.py
```

unless the purpose is genuinely generic and documented.

---

# 20. Class Naming

Classes must represent meaningful concepts.

Good:

```text
ERCContextBuilder
EnterpriseApiExecutor
PromptResolver
GuardrailValidator
AgentExecutionHarness
```

Avoid:

```text
Manager
Processor
Handler
Helper
Service
```

when the name does not explain responsibility.

# 21. Function Naming

Functions should describe actions.

Examples:

```text
build_erc_context()
retrieve_documents()
execute_tool()
```

# 22. Constants

Centralize meaningful constants.

Examples:

```text
MAX_ERC_BATCH_SIZE
DEFAULT_TIMEOUT_SECONDS
MAX_AGENT_ITERATIONS
MAX_TOOL_CALLS
```

Do not scatter magic numbers throughout the codebase.

# 23. Magic Numbers

```python
if count > 20:
```

```python
if count > MAX_ERC_BATCH_SIZE:
```

# 24. Async Programming

Use async programming for I/O-bound operations.

Examples:

```text
HTTP
Enterprise APIs
RAG

```

---

# 25. Blocking Code

Do not execute blocking operations directly inside the async event loop.

Avoid:

```python
requests.get(...)
```

inside an async execution path.

Use appropriate async clients or controlled worker execution.

---

# 26. HTTP Client Standard

Use a shared HTTP client abstraction.

Requirements:

```text
Connection pooling
Timeout
Retry
Tracing
Correlation
Circuit breaker where required
```

Avoid creating a new client for every request.

---

# 27. FastAPI Standard

FastAPI endpoints must remain thin.

Endpoint responsibilities:

```text
Validate request
Build request context
Invoke application/orchestration layer
Return response
```

Do not place complete agent orchestration inside route functions.

```json
  "links": [],
  "errors": []
```

# 33. LangGraph Standard

LangGraph is the workflow orchestration mechanism.

It should represent:

```text
State
Nodes
Edges
Conditional routing
Loops
Parallel branches
Checkpoints
Termination
```

---

# 34. LangGraph Graph Design

Each graph should have a clearly defined:

```text
Input state
Output state
Nodes
Transitions
Failure paths
Termination conditions
```

---

# 35. LangGraph State

State must contain only information required for workflow execution.

Do not place:

```text
Secrets
Unbounded raw data
Uncontrolled conversation history
```

into graph state.

---

# 36. Typed Graph State

Graph state should be strongly typed.

Example:

```python
class WorkflowState(TypedDict):
    request_id: str
    conversation_id: str
    intent: str
    erc_context: ERCContext | None
    results: list[AgentResult]
    status: str
```

---

# 37. LangGraph Node Standard

Each node must have:

```text
Single responsibility
Defined input
Defined output
Error handling
Observability
Test coverage
```

---

# 38. LangGraph Edge Standard

Edges should represent business/workflow conditions.

Avoid deeply nested routing logic inside nodes.

---

# 39. Conditional Routing

Use explicit routing functions.

Example:

```text
Supervisor
 ├── ERC workflow
 ├── RAG workflow
 ├── Information workflow
 └── Clarification
```

---

# 40. Graph Loops

Every loop must have explicit termination controls:

```text
Maximum iterations
Maximum duration
Maximum tool calls
Maximum model calls
```

---

# 41. Parallel Graph Execution

Parallel execution is allowed for independent operations.

Example:

```text
        ┌── Team API
        ├── Official API
Agent ──┼── Course API
        └── RAG
```

Aggregation must occur after required branches complete.

---

# 42. Sequential Graph Execution

Use sequential execution where output dependency exists.

Example:

```text
API A
 ↓
API B
 ↓
API C
```

```python
        ...
```

# 202. Final Development Principles

1. **Treat AI code as production enterprise software.**
2. **Keep FastAPI endpoints thin and delegate orchestration to the application/runtime layer.**
3. **Use LangGraph for explicit workflow state, routing, loops and parallel execution.**
4. **Keep agents as workflow-level logical capabilities unless a separate service is justified.**
5. **Keep the supervisor responsible for routing, not business-rule ownership.**
6. **Use the harness to enforce runtime execution limits and safety controls.**
7. **Use typed contracts at all important boundaries.**
8. **Prefer async I/O for external dependencies.**
9. **Use shared connection pools.**
10. **Never allow unbounded agent loops or retries.**
11. **Separate provider abstractions from business/application logic.**
12. **Keep enterprise APIs authoritative for enterprise data and business rules.**
13. **Transform external API payloads into controlled internal context models.**
14. **Treat prompts, models, graphs, agents and configuration as versioned software artifacts.**
15. **Never hard-code secrets or provider credentials.**
16. **Validate configuration before runtime execution.**
17. **Every external dependency must have timeout and failure handling.**
18. **Every retried operation must consider idempotency.**
19. **Every important component must have structured observability.**
20. **Every AI capability must have appropriate evaluation coverage.**
21. **Security must be enforced in code and infrastructure, not only in prompts.**
22. **Untrusted content must never become privileged instructions.**
23. **Model output must be validated before privileged actions.**
24. **Engineering Agents must not bypass mandatory quality gates.**
25. **Generated code must pass the same review and testing standards as human-written code.**
26. **Production dependencies must be reproducible and version controlled.**
27. **PRs must explain architecture, security, testing and AI impact.**
28. **Breaking changes require explicit versioning and migration planning.**
29. **AI changes require evaluation, not only unit tests.**
30. **Performance and cost impact must be considered for agent, prompt, model and RAG changes.**
31. **Documentation must evolve with implementation.**
32. **Architecture compliance must be continuously checked.**
33. **The platform must remain provider-independent where practical.**
34. **The platform must remain enterprise-authoritative rather than inventing business rules.**
35. **The final development standard is: secure, typed, tested, observable, versioned, evaluated, reviewable and production-ready code.**
