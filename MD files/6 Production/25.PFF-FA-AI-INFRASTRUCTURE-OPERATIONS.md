# 27. Identity Architecture

Use managed identities wherever supported.

Preferred:

```text
AKS workload
 ↓
Managed Identity
 ↓
Azure resource
```

Avoid long-lived service credentials.

> **PFF AI decision (ADR-D5-07 / ADR-D5-20 — enterprise application standard).** The
> general preference above notwithstanding, PFF AI establishes its **Azure Key Vault**
> connection **only** through the enterprise **service principal (MI-SPN)** — tenant id +
> client id + client secret, held in the Azure DevOps pipeline variable group and injected
> into the workload environment. This is the mandated, sole method for the Key Vault
> connection on this platform: no `DefaultAzureCredential`, no CLI/interactive credential,
> and no managed identity without an explicit SPN. Other resources may still use managed
> identity where the enterprise standard does. Realized in
> `src/pff_fa_ai/configuration/secrets.py`.

# 135. Final Infrastructure Principles

1. **Infrastructure must be repeatable and version controlled.**
2. **Production environments must be isolated from non-production environments.**
3. **APIM remains the enterprise authorization boundary.**
4. **FastAPI is the AI platform API boundary for the presentation layer.**
5. **Business rules remain in the enterprise application.**
6. **Agents remain logical workflow capabilities rather than mandatory microservices.**
7. **Container images must be immutable and traceable.**
8. **Production images must not use `latest`.**
9. **Managed identity is preferred over long-lived credentials.**
10. **Secrets must remain outside source code and images.**
11. **Private connectivity should be preferred for sensitive Azure resources.**
12. **Outbound internet access must be controlled.**
13. **AI workloads require capacity planning beyond CPU alone.**
14. **SLM infrastructure must support the current API model and future self-hosted model.**
15. **Environment configuration must be versioned and environment-specific.**
16. **Infrastructure must be deployed through IaC.**
17. **CI/CD must enforce quality and security gates.**
18. **Production deployment must use immutable artifacts.**
19. **Application, prompt, model, configuration and AI component versions must remain traceable.**
20. **Rollback must consider AI dependencies, not only application code.**
21. **Health probes must distinguish process health from dependency health.**
22. **Critical workloads must support high availability.**
23. **Scaling must consider AI-specific bottlenecks.**
24. **ERC workloads must be capacity tested for 100+ entities.**
25. **Backups must be restored periodically to prove recoverability.**
26. **DR must define RTO and RPO for critical components.**
27. **DR must be tested, not merely documented.**
28. **Production readiness requires application, AI, security, infrastructure and operational evidence.**
29. **Infrastructure drift must be detected and controlled.**
30. **Every production release must have a traceable release manifest.**
31. **Deployment validation must verify both technical health and AI dependency health.**
32. **Production infrastructure must fail safely and recover predictably.**
33. **Infrastructure must enable the AI platform without becoming the owner of enterprise business rules.**
34. **The final production platform must be reproducible, observable, scalable, secure and recoverable.**
