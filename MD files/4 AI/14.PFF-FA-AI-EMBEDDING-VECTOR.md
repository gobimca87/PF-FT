# 2. Core Principle

> **The embedding/vector layer is a retrieval infrastructure capability. It does not own document truth, business rules, authorization decisions, or final answer generation.**

The capability converts approved content chunks into searchable vector representations and provides controlled retrieval infrastructure to the RAG layer.

# 17. Embedding Dimension

An embedding is represented as:

```text
Vector = [x1, x2, x3, ... xn]
```

where:

```text
n = embedding dimension
```

Examples may include:

```text
384
512
768
1024
1536
```

The actual production dimension must be determined by the selected model.

---

# 18. Dimension Is an Architecture Constraint

The vector index must be created for the embedding dimension.

Example:

```text
Embedding model
dimension = 768

Vector index
dimension = 768
```

Mismatch must fail validation.

---

# 19. Dimension Validation

Before indexing:

```python
if len(vector) != configured_dimension:
    raise EmbeddingDimensionMismatch()
```

Before searching:

```python
if len(query_vector) != index_dimension:
    raise EmbeddingDimensionMismatch()
```

# 36. ANN Search

```text

```

The choice depends on the selected vector platform.

# 37. HNSW

HNSW provides graph-based approximate nearest-neighbor search.

Important tuning dimensions include:

```text
M
efConstruction
efSearch
```

These must be evaluated against:

```text
recall
latency
memory
index-build time
```

---

# 38. IVF

IVF partitions vectors into clusters.

Important considerations:

```text
number of clusters
search probes
build cost
recall
latency
```

Use only if supported and justified by the selected platform.

---

# 39. Product Quantization

PQ can reduce storage/memory requirements.

Trade-offs:

```text
lower memory
lower storage

additional complexity
```

Evaluate before production.

# 40. Similarity Metrics

Common metrics:

```text
Cosine Similarity
Dot Product
Euclidean Distance
```

The selected metric must match the embedding model and vector-store configuration.

---

# 41. Cosine Similarity

Conceptually:

```text
cos(A,B) = (A · B) / (||A|| ||B||)
```

Useful when direction matters more than magnitude.

---

# 42. Dot Product

```text
A · B
```

Can be used where model/index assumptions support it.

---

# 43. Euclidean Distance

```text
distance(A,B)
```

Lower distance indicates greater similarity.

---

# 182. Final Design Principles

1. **Embedding is a dedicated platform capability.**
2. **RAG consumes embedding/vector services; the responsibilities remain separate.**
3. **Embedding providers are abstracted behind a stable interface.**
4. **The initial provider can be Hugging Face API while retaining a self-hosted model boundary.**
5. **Model selection must be based on PFF-FA retrieval evaluation.**
6. **Embedding dimensions are explicit architecture parameters.**
7. **Document and query embeddings must remain compatible.**
8. **One logical chunk maps to one primary embedding vector unless a specialized strategy is approved.**
9. **Every vector retains document/chunk provenance.**
10. **Metadata is essential to enterprise retrieval.**
11. **Security metadata is mandatory for protected content.**
12. **Tenant and organization isolation must be enforced at retrieval infrastructure level.**
13. **The SLM must never construct unrestricted vector filters.**
14. **The application constructs filters from validated authorization context.**
15. **Vector search and keyword search complement one another.**
16. **Hybrid retrieval remains orchestrated by RAG.**
17. **Similarity metrics must be explicitly configured.**
18. **ANN configuration must be evaluated against quality and latency.**
19. **Embedding operations should be batched and idempotent.**
20. **Unchanged chunks should not be unnecessarily re-embedded.**
21. **Vector indexes must be versioned.**
22. **Embedding models and indexes must have explicit compatibility.**
23. **Model/dimension changes normally require controlled re-indexing.**
24. **Vector indexes must be rebuildable from canonical chunks and configuration.**
25. **Index migration should support controlled cutover and rollback.**
26. **Vector deletion must propagate according to the data lifecycle policy.**
27. **Embedding and vector infrastructure must be observable.**
28. **Sensitive embeddings and metadata must not be unnecessarily logged.**
29. **Cost and capacity must be continuously measurable.**
30. **Embedding quality must be evaluated using PFF-FA-specific datasets.**
31. **Hard negatives are important for enterprise entity retrieval.**
32. **Cross-tenant and ACL leakage tests are mandatory.**
33. **Embedding changes require RAG regression evaluation.**
34. **The vector layer must never become the source of business truth.**
35. **The complete chunk → embedding → index → search → RAG evidence path must be traceable.**
