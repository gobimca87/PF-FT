# PFF-FA Enterprise Agentic AI Platform — AI Guardrails

**Document ID:** 18.PFF-FA-AI-GUARDRAILS  
**Logical Capability:** PFF-FA-AI-GUARDRAILS  
**Phase:** Phase 4 — AI  
**Version:** 1.0.0  
**Status:** Development Baseline  
**Platform:** PFF-FA Enterprise Agentic AI Platform / Adam AI  
**Runtime:** Python / FastAPI / LangGraph  
**Primary Scope:** Complete AI safety and control layer covering input validation, prompt-injection defense, jailbreak protection, output validation, PII/secrets protection, tool restrictions, Enterprise API restrictions, MCP restrictions, hallucination controls, authorization-context enforcement, content/data boundaries, model safety, security scanning and AI evaluation.

---

# 1. Purpose

This document defines the enterprise AI Guardrails architecture for the PFF-FA AI platform.

Guardrails provide a defense-in-depth control layer around:

```text
User input
Conversation context
ERC
Memory
RAG
Enterprise APIs
Tools
MCP
Service Bus events
Portal content
SLM input
SLM output
Agent execution
Workflow execution
```

The guardrail layer is responsible for preventing unsafe, unauthorized, untrusted, malformed, unsupported or policy-violating AI behavior.

---

# 2. Core Principle

> **The model is never the final security or authorization boundary.**

Guardrails supplement—not replace:

```text
APIM authorization
Enterprise authorization
Enterprise policy engines
Enterprise business rules
Network security
Identity
Data access controls
Application validation
```

# 8. Trust Classification

Examples:

| Source | Trust |
|---|---|
| System prompt | SYSTEM_TRUSTED |
| Platform configuration | APPLICATION_TRUSTED |
| Enterprise API result | ENTERPRISE_AUTHORITATIVE |
| Enterprise policy result | ENTERPRISE_AUTHORITATIVE |
| Approved RAG evidence | CONTROLLED_CONTEXT |
| User message | UNTRUSTED_USER |
| External document | UNTRUSTED_EXTERNAL |
| External website content | UNTRUSTED_EXTERNAL |
| Unknown tool payload | UNKNOWN |

Trust metadata must be assigned by the application and cannot be controlled by the model or user.

# 185. Final Design Principles

1. **Guardrails are a mandatory platform control layer.**
2. **Guardrails never replace enterprise authorization.**
3. **APIM remains the primary enterprise authorization boundary.**
4. **The model is never trusted to enforce its own security boundary.**
5. **User input is untrusted.**
6. **Retrieved content is data, not instructions.**
7. **Enterprise API responses are authoritative data but are not executable instructions.**
8. **Tool outputs are validated before entering model context.**
9. **MCP servers and tools are explicitly allowlisted.**
10. **Arbitrary model-generated URLs are prohibited for enterprise API execution.**
11. **Tool parameters are schema-validated and authorization-checked.**
12. **Unknown tools and unknown MCP servers are blocked.**
13. **Structured model output is validated before downstream use.**
14. **Invalid output never directly drives enterprise actions.**
15. **PII and secrets are detected and protected.**
16. **Secrets are never stored in prompts or configuration.**
17. **Data classification controls what can be sent to external SLM providers.**
18. **Hallucination is controlled through grounding, evidence and validation.**
19. **Enterprise deterministic rules remain authoritative.**
20. **Memory cannot override current authorization or authoritative enterprise results.**
21. **RAG ACLs are enforced before retrieval context reaches the model.**
22. **ERC batching must preserve entity integrity and prevent cross-batch contamination.**
23. **Service Bus events must be schema-validated and idempotent.**
24. **Portal links must come from the approved portal-link catalog.**
25. **Models must come from an approved model registry.**
26. **Model routing must be policy-controlled.**
27. **Security-sensitive guardrails fail closed.**
28. **Guardrail changes are versioned and evaluated.**
29. **Security regression testing is mandatory for guardrail releases.**
30. **Adversarial evaluation is part of the release process.**
31. **Guardrail decisions are observable without exposing sensitive payloads.**
32. **Guardrail failures are typed, auditable and traceable.**
33. **Guardrail configuration is immutable at runtime unless explicitly governed.**
34. **AI agents cannot disable or modify guardrails.**
35. **Every workflow execution must be traceable to guardrail versions.**
36. **Guardrail effectiveness must be measured continuously through AI evaluation.**
37. **Security controls must be independent enough that failure of one control does not automatically disable the entire safety boundary.**
38. **The platform must prioritize security and correctness over model convenience.**
