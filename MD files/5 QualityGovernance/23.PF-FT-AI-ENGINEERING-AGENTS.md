# 1. Purpose

This document defines the engineering-agent framework used to automate software quality, validation, security, AI evaluation, documentation and engineering governance for the PF-FT AI platform.

Engineering agents are not business workflow agents.

They operate around the software-development lifecycle:

```text
Developer
   ↓
Git / Pull Request
   ↓
Engineering Agent Orchestration
   ↓
Validation Agents
   ├── Unit Test Agent
   ├── Code Review Agent
   ├── Security Scan Agent
   ├── Dependency Agent
   ├── Prompt Review Agent
   ├── AI Evaluation Agent
   ├── Test Generation Agent
   ├── Documentation Agent
   ├── Configuration Agent
   ├── API Contract Agent
   ├── RAG Validation Agent
   ├── Model/SLM Agent
   ├── Guardrail Agent
   └── Observability Agent
   ↓
Quality / Security / AI Gates
   ↓
Human Review where required
   ↓
CI/CD
```

---

# 2. Core Principle

> **Engineering agents assist and enforce engineering quality; they do not become an unrestricted autonomous software deployment authority.**

Engineering agents may:

```text
Inspect
Analyze
Validate
Generate
Suggest
Test
Report
Create remediation proposals
Create pull-request comments
Create controlled code changes where explicitly permitted
```

They must not independently bypass:

```text
Security controls
Branch protection
Production approval
Authorization
Governance
Mandatory testing
Human approval boundaries
```

# 11. Engineering Agent Permission Levels

Recommended:

```text
LEVEL 0 — Read only
LEVEL 1 — Report
LEVEL 2 — Generate test/documentation
LEVEL 3 — Create proposed changes

```

---

# 12. Least Privilege

Each engineering agent receives only the permissions required.

Example:

```text
Unit Test Agent
 → repository read/write to test scope

Security Agent
 → repository read

Documentation Agent
 → documentation scope

PR Agent
 → PR comments / controlled branch

Deployment
 → CI/CD only
```

# 138. Final Engineering Agent Principles

1. **Engineering agents are software-quality assistants, not unrestricted autonomous developers.**
2. **The Engineering Agent Supervisor selects agents based on change impact.**
3. **Independent engineering checks should run in parallel.**
4. **Dependent checks must execute sequentially.**
5. **Every engineering agent has a defined responsibility.**
6. **Every engineering agent has explicit permissions.**
7. **Read-only is the default permission.**
8. **Automated code modification requires explicit enablement.**
9. **Production deployment is not an implicit engineering-agent capability.**
10. **Security controls cannot be disabled by engineering agents.**
11. **Engineering-agent prompts are governed artifacts.**
12. **Repository content is untrusted input and cannot override agent instructions.**
13. **Every engineering agent must be evaluated.**
14. **Every engineering agent must have regression tests.**
15. **Every agent execution must be traceable.**
16. **Every finding must have severity and evidence.**
17. **Critical security findings block release.**
18. **Mandatory validation-agent failures block the quality gate unless an approved exception exists.**
19. **Automated remediation must create auditable changes.**
20. **Human approval remains mandatory for high-risk engineering actions.**
21. **Unit Test Agent must never weaken tests to obtain a pass.**
22. **Code Review Agent must distinguish defects from suggestions.**
23. **Security Agent must not suppress findings without approved governance.**
24. **Dependency Agent must identify transitive risks.**
25. **Prompt Review Agent must detect instruction and security conflicts.**
26. **AI Evaluation Agent must protect behavioral quality.**
27. **RAG Validation Agent must verify retrieval and ACL behavior.**
28. **Model/SLM Agent must verify approved model compatibility.**
29. **Guardrail Agent must validate both security and usability.**
30. **Observability Agent must ensure telemetry without sensitive-data leakage.**
31. **Architecture Compliance Agent must detect implementation drift.**
32. **Engineering-agent orchestration must be versioned.**
33. **Engineering-agent configuration must be environment-aware.**
34. **Engineering-agent model and prompt versions must be traceable.**
35. **The engineering-agent platform must improve software quality without becoming a bypass around enterprise governance.**
